## 做了什么

1. **YOLO 检测**：
   - 数据：YOLO 布局（VOC 版先用 `convert_voc_to_yolo.py` 转，8:2 划分 train/valid）；

   - 训练：epochs=30、imgsz=640、batch=16；训练后 `model.val()` 输出 mAP50/mAP50-95/mP/mR，
     存 `results/week2_3/yolo_results.csv`；另取 3 张验证图预测可视化存
     `results/week2_3/yolo/predict/`。
   - 结果（真实数据 30 epochs，第 30 轮最优）：mAP50 = 0.7703；mAP50-95 = 0.4362；
     mP = 0.7249；mR = 0.7134（验证集 360 张图 / 828 个标注框）。
     分类别 mAP50：patches 0.947、scratches 0.931、inclusion 0.873、pitted_surface 0.786、
     rolled_in_scale 0.666、crazing 0.418——龟裂细密、目标小，是最难的一类。
2. **设备运维诊断智能体（`src/agent-maintenance/`）**：
   - `anomaly.py`：`IsolationDetector`（n_estimators=200），用 `features.csv` 中健康期
     （stage=0）样本训练；也支持"其他轴承历史数据训练 + 未训练轴承回测"两种方式；
   - `diagnose.py`：诊断链路 = 特征提取 → 异常判定 →（异常时）分类模型判健康阶段、
     RUL 模型估寿命、包络谱证据定位故障元件（BPFO 外圈 / BPFI 内圈 / BSF 滚动体 / FTF 保持架）；
   - `llm.py`：DeepSeek 客户端，读环境变量或本地 `.env` 中的 `DEEPSEEK_API_KEY`；没有 key 或调用失败自动降级；
   - `report.py`：结构化报告渲染（诊断结论/证据链/处置建议/寿命监测计划），
     大模型走 system prompt 约束（事实必须来自输入，不得编造数值）；
   - `main.py`：对话界面，`/scan` `/report` `/ask` 模拟"工人提问 → Agent 诊断"。
3. **演示输出（真实模型实测，记录见 `results/logs/agent_maintenance_demo.log`）**：

## 遇到的问题与解决过程

**问题 1：`yolov8n.pt` 预训练权重从 GitHub 下载失败。**

```
HTTPError / ConnectionError: github release 下载超时
```

排查：机房网络访问 GitHub release 不稳定；ultralytics 默认从 GitHub 拉权重。
解决：改用国内镜像 `hf-mirror.com/Ultralytics/YOLOv8` 用 curl 下载 `yolov8n.pt` 放到项目根目录，
ultralytics 优先使用本地文件，微调正常启动，30 epochs 最终 mAP50=0.7703。
此前先用 `--from-scratch` 试跑过 5 个 epoch，mAP50 只有 0.105（权重保存为
`results/week2_3/yolo/train_scratch`），因此正式实验采用预训练微调，并在报告中注明初始化方式。

**问题 2：智能体没有 DeepSeek API key，演示时可能断网。**

解决：设计成"API 优先、离线降级"双通道：有 key 时大模型按结构化模板写报告；
无 key/失败时 `report.py::offline_report()` 用规则引擎按特征数值套模板生成，
两个通道输出同一结构（结论/证据链/处置建议/监测计划），离线演示不怯场。
后续把 key 写入本地 `.env`（已被 `.gitignore` 忽略）并完成 DeepSeek 在线联调。

**问题 3：包络谱定位故障元件的判据容易误报。**

排查：单文件、小故障幅值下 BPFO/BPFI 幅值差可能只是噪声。
解决：把四个特征频率的幅值都写进报告"证据链"（不只给结论），并注明是工程近似；
轴承几何参数已按《数据集解读》表 1 核实为 LDK UER204（Z=8、d=7.92、D=34.55、α=0°），
内置默认值即为真实值，无需再手工传参。
