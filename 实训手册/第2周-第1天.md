## 做了什么

1. **PyTorch 环境**：Mac 上 `pip3 install torch torchvision`（arm64 CPU/MPS 版），
   运行 `01_verify_env.py` 输出版本、CUDA 设备数、cuDNN、MPS 可用性与矩阵乘法自检：
   torch=2.15.0；本机无 CUDA，Apple MPS 可用，训练设备自动选 `mps`。
   机房 Windows + NVIDIA 显卡的同学按指南用南京大学镜像装 cu126 版。
2. **RNN 分类实现**：
   - 数据：`common/dl.py` 的 `load_sequences()` 按 `features.csv` 的 `file_path` 列映射回原始
     CSV，取垂直通道降采样到 `--seq-len 256` 点，按序列 z-score 归一化；
   - 标签：沿用第 1 周健康阶段三分类（0 健康/1 退化/2 故障）；
   - 划分：与第 1 周一致的按轴承留出（`bearing_split_mask`）；
   - 模型：`nn.RNN(input=1, hidden=64, layers=2, tanh)` → 取末步隐状态 → 全连接三分类；
   - 训练：Adam，lr=1e-3，batch=64，epochs=20；每轮记录训练/测试损失与测试准确率。
3. **运行**：
   `python3 src/week2-bearing-dl/02_rnn_classifier.py --features results/week1/features.csv`
4. **结果（真实数据实测）**：RNN 测试集准确率 = 0.8347，但混淆矩阵显示 3151 个测试样本
   **全部判成"健康"**（2630 健康 + 323 退化 + 198 故障 全进同一格）——0.8347 恰好等于
   测试集健康类占比，macroF1 只有 0.3033。对照第 1 周 RandomForest：准确率 0.7820 但
   macroF1 0.7202。结论：准确率高 5 pp 是假象，RNN 实际没有识别出退化/故障；
   跨轴承时绝对幅值分布差异远大于阶段差异，逐序列 z-score 后阶段信息被进一步削弱，
   模型选择"全判健康"最省损失。

## 遇到的问题与解决过程

**问题 1：RNN 训练 loss 从 0.57 缓降到 0.52 后几乎不动，测试准确率第 1 轮就是 0.8347。**

```
epoch 1  train_loss=0.573  test_loss=0.610  test_acc=0.8347
epoch 20 train_loss=0.525  test_loss=0.595  test_acc=0.8347
```

排查：0.8347 = 测试集健康类占比，模型输出塌缩到多数类；训练损失下降只是把健康类的
概率推得更高，退化/故障从未被预测。根因是跨轴承幅值不可迁移 + 序列级 z-score 抹掉
绝对能量信息，端到端模型没有学到与阶段相关的形态差异。
解决：本次保留为负面对照，并据此把"逐轴承健康基线归一化、加入工况特征"列为改进方向
（见报告 5.7）；分类主力仍用第 1 周的手工特征 + RandomForest。

**问题 2：Mac 上 `torch.cuda.is_available()` 是 False，担心环境装错。**

排查：Mac 无 NVIDIA GPU，`cuda` 接口为 False 是正常的；本机可用 Apple MPS。
解决：`pick_device()` 依次探测 cuda → mps → cpu，脚本自动适配，不用改代码。
